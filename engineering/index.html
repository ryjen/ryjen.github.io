Engineering Work

By Robert Ryan Jennings 5 min read

I work on long-lived software across native mobile applications, backend services, platform tooling, and security-sensitive integration. Professionally, that includes production mobile and backend delivery, modernization, and cross-team engineering work. The examples below are independent engineering projects and public research, except for the explicitly labeled OpenArchive collaboration. Some projects publish their implementation; others publish specifications, conformance assets, or independently verifiable release artifacts.

The common thread is keeping authority, state, and failure behavior explicit, whether the system is a mobile application, a repository controller, or an AI-assisted engineering environment.

Current engineering focus

Much of my independent work now lives under Micrantha, where I study how software can become more autonomous without surrendering control over code, data, credentials, or infrastructure.

The main engineering question is how to separate reliance on model-assisted reasoning from the deterministic mechanisms that authorize, execute, and verify its effects. These projects have different responsibilities rather than one framework that attempts to own everything.

Selected case studies

Governed agent effects — Anthesis Governance Lab

An independent public trial of deterministic governance for AI-assisted software delivery. The lab lets a reviewer examine approved, denied and adversarial scenarios using a signed Rust anthesis-lab release, canonical fixtures and reproducible verification commands. It does not require a live model, a private source checkout, or a GitHub token.

The lab is deliberately not the production runtime. Its results demonstrate bounded trial behavior, not that every agent integration enforces the same controls.

Five-minute walkthrough · Verification runbook

On-device inference with application-owned authority — Amaryllis

An open-source, evolving React Native SDK for native Android and iOS inference, streaming interaction and offline-first context interfaces. The application owns model selection, storage, rendering and fallback behavior. Model-generated component data is validated against registered contracts rather than executed as generated UI code.

The active 0.1.x implementation is not a stable API or a general claim of model safety.

Source and architecture

Configuration as a reviewed state transition — Config Drift Guard

An independent internal-platform vertical slice, not a deployed enterprise control plane. The important decision was to separate observed configuration, immutable proposed remediation, approval, mutation, and verification. Fastify, SQLite and a Next.js operator UI make the run observable; stale-plan checks prevent approval of a changed state.

Source, five-minute demo and failure scenarios

Mobile authority without a mandatory backend — Eyespie

An independent, closed-alpha Kotlin Multiplatform application. The Wayfinder implementation uses SQLDelight for authoritative local state, native CameraX/AVFoundation boundaries, MediaPipe embeddings and signed versioned .eyespie game interchange. The former Supabase design is historical.

Android automation and selected signed-artifact checks exist, but cross-device physical acceptance, iOS signed distribution, and the final closed-alpha release gate remain outstanding.

Source, architecture and candidate-bound acceptance criteria

Reversible filesystem changes despite untrusted AI — tidyfs

An independent Rust CLI combining deterministic filesystem classification and cleanup eligibility with optional advisory model output. The model cannot authorize mutation, override exclusions, or determine reclaimable bytes. Changes require explicit interactive approval and use reversible quarantine with recovery evidence, rather than permanent deletion.

CLI, recovery model and threat model

Honest partial failure in Git mirroring — Repora

An independent pre-alpha Go CLI that models repository topology, observation, exact ref plans, authorization, stale-head preflight and per-target execution evidence. It intentionally records incomplete mirror convergence instead of presenting independent remote operations as atomic.
